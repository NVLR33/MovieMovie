# Трейлеры материалов

## Контент

`mg_movies.trailer_url` — отдельная HTTPS-ссылка, не `watch_url`. Пустая строка
означает отсутствие трейлера. Администратор/модератор редактирует её в форме
материала; редактор может добавить при создании. Предложка принимает ссылку и
проходит ту же серверную проверку, утверждение сохраняет поле в материал.
Никакого автоматического поиска, скачивания с видеохостингов или обхода их
ограничений нет: редактор указывает источник явно.

Поддерживаются прямые MP4/WebM (в том числе подписанный URL с query), ссылки
YouTube, Rutube и штатный `video_ext.php` VK. Произвольные iframe, HTML, HTTP,
учётные данные в URL и data/Base64 запрещены. Сервер не скачивает внешние ссылки.
Провайдеры нормализуются существующим allowlist `playerEmbedUrl`; iframe имеет
sandbox, referrer-policy и не получает доступ к DOM сайта. Прямые ссылки должны
вести на доверенный HTTPS CDN, иметь корректный Content-Type, поддержку Range
и браузерный кодек; расширение файла само по себе не гарантирует воспроизведение.

## Предпросмотр

Видео/iframe отсутствуют в DOM до удержания мыши над постером 650 мс. Предпросмотр
длится максимум 20 секунд, без звука, без циклического повтора. Одновременно активен
только один; уход мыши, прокрутка, скрытие вкладки или потеря фокуса его останавливает
и удаляет источник из DOM. Не запускается на touch/coarse-pointer, при Save-Data
или reduced-motion. Постер и переход на материал остаются доступны.

Hover реализован для прямого видео и YouTube nocookie с mute=1. Rutube/VK оставлены
для явного открытия: гарантировать одинаковый muted autoplay у всех провайдеров
нельзя. На странице материала есть кнопка «Трейлер» для всех поддержанных источников,
в том числе телефона и клавиатуры. Диалог удерживает фокус, закрывается Escape,
возвращает фокус кнопке; есть ссылка на источник, если плеер заблокирован.
Провайдер может запретить embedding, не работать в регионе или требовать согласие;
сайт не обещает обойти эти ограничения. Внешний iframe загружается только после
наведения/нажатия, а не для каждой карточки каталога.

## Собственная загрузка (требует отдельной настройки)

`POST /api/trailers` принимает сырой `video/mp4` или `video/webm`, максимум **40 MiB**.
Только вошедшие пользователи с правом создания материалов; same-origin проверка,
повторная проверка прав из БД, потоковый лимит тела и проверка сигнатуры контейнера.
Лимит **6 попыток в час на редактора** сериализуется блокировкой пользователя и
учитывается в admin audit, работает между инстансами. Серверный Storage-ключ никогда
не уходит браузеру. Для обычной предложки доступен URL, не загрузка видео.

Используется **отдельный bucket `trailers`**, public read, 40 MiB,
`video/mp4`, `video/webm`; клиентских политик записи нет. Изображения остаются
в прежнем `uploads` с 4 MiB. Не хранить видео в PostgreSQL/Base64/Git.

Подготовлены, но **не запускались в production**:

1. Аддитивная миграция `20261122-zzzzz-trailers.sql` (и обновлённый SQL bundle).
   Перед выкладкой кода выполнить штатную проверенную процедуру миграции/backup.
2. `npx tsx scripts/setup-trailer-storage.ts` — только после согласования владельцем
   хранилища. Создаёт отдельный bucket, существующий с отличающимися настройками
   автоматически не меняет. Использует прежние серверные переменные Supabase Storage.
3. Reverse proxy должен разрешать тело 40 MiB и достаточный upload timeout. Платформы
   с меньшим лимитом serverless-body потребуют будущей presigned/direct-upload схемы;
   текущая загрузка идёт через сервер. URL на готовый CDN-файл работает без upload API.

Если bucket/окружение не настроены, редактор видит ошибку и может использовать URL.
Загрузка проверяет контейнер, но не транскодирует, не сканирует и не подтверждает
кодеки/права на контент. Рекомендуются короткие H.264/AAC MP4 (faststart) или WebM,
загруженные уполномоченным редактором. Загруженный файл связывается с материалом
только после сохранения формы. Отмена/замена не удаляет файл автоматически: удалять
осиротевшие объекты вручную по сверке с `trailer_url`, с запасом времени для открытых
форм и резервных копий. S3-перенос и изменения существующего storage не выполнялись.
