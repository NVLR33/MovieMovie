# Достижения: четыре уровня и подробный учёт сериалов

## Обычные достижения

33 достижения имеют уровни **Бронза → Серебро → Золото → Платина**.
Пороги находятся в `src/lib/achievements.ts` и используются одним серверным
вычислителем, страницей достижений, статистикой редкости и карточкой киномана.
Старые счётчики не обнуляются. Прежние три порога сохранены, кроме двух ограниченных
шкал: категории теперь 1/2/4/6, игровые режимы 4/8/12/16. Здесь прогресс может только
повысить прежний уровень, не понизить его.

Редкость и уровень — разные показатели. Для каждого из четырёх уровней считается
доля владельцев среди всех зарегистрированных пользователей. Обычные достижения
по-прежнему зависят от текущего прогресса; календарные правила используют UTC.
Новых начислений XP за уровни нет.

### Археолог

1 / 5 / 20 / 50 **разных** просмотренных материалов категории «Фильм»,
с известным годом от 1888 до 1959 включительно. Повторные просмотры не прибавляют
прогресс, сериалы и неизвестные годы исключены. В каталоге есть фильтр «До 1960 года».

### Серийный маньяк

1 / 3 / 5 / 10 полностью оценённых сериалов. Старая ачивка `series` за просмотры
сериалов сохранена отдельно под названием «Любитель сериалов».

Для нового достижения требуется:
- сериал, мультсериал или аниме-сериал;
- редактором подтверждённый полный список сезонов и эпизодов;
- минимум 10 эпизодов суммарно;
- отдельная оценка каждого сезона и каждого эпизода от 0.5 до 10, шаг 0.5.

Общая оценка сериала эти оценки не заменяет. Никакие сезоны или названия
из одного числового поля `episodes` не генерируются автоматически.

## Редактор сезонов

1. Открыть карточку сериала под администратором или модератором.
2. Нажать «Редактировать сезоны».
3. Внести реальные сезоны с номерами от 1 и числом эпизодов (1–100 в сезоне).
   При желании заполнить названия сезонов и эпизодов.
4. Нажать «Подтвердить полный список». Сезоны и серии должны идти подряд от 1.

После изменения структуры полноту нужно подтвердить заново. При уменьшении числа
эпизодов удаляются только последние лишние эпизоды и их оценки; сохранённые эпизоды
оставляют прежние ID и оценки. Удаление сезона удаляет его эпизоды и оценки.
Эти действия требуют подтверждения в интерфейсе.

Последняя отдельная оценка в полном каталоге фиксирует сериал в постоянном журнале.
Если все оценки поставлены до подтверждения редактором, достаточно обновить любую
из них после подтверждения. Чтение GET ничего не выдаёт и не изменяет.
Уже засчитанный сериал остаётся у пользователя даже после добавления сезона,
изменения/удаления оценки или удаления карточки сериала. Повторная оценка не создаёт
второго завершения и повторного уведомления. Дополнительного XP нет.

Гости видят структуру, но для оценок входят в аккаунт. API возвращает только свои
оценки; чужие пользовательские оценки по сезонам/эпизодам не перечисляются.
Изменения каталога проверяют роль на сервере. Подмена ID эпизода/сезона другого
сериала отклоняется. Новые таблицы закрыты RLS и REVOKE для Supabase browser API.

## Скрытый «Первопроходец»

Пользователь первым отмечает **фильм** просмотренным, затем добавляет оценку и
самостоятельный отзыв от 80 Unicode-символов (не ответ в обсуждении).
Оценка и отзыв после открытия допустимы в любом порядке; редактирование своего
отзыва до нужной длины тоже учитывается. Более ранние оценки/отзывы без первого
просмотра сами по себе не открывают награду: после фиксации просмотра их нужно
обновить. Порог отзыва отличает его от короткой реплики.

Первый зритель фиксируется навсегда в момент просмотра. Действия разных пользователей
по одному фильму сериализуются блокировкой строки фильма. Удаление/повторная отметка
просмотра не передаёт первенство. Одна награда и одно уведомление на пользователя,
без дополнительного XP; награда не отбирается при дальнейших изменениях активности.
Закрытые имена и правила не передаются в клиентский список скрытых трофеев.

Миграция не назначает первых зрителей задним числом: уже просмотренные материалы
блокируются на основе существующих просмотров и событий. Полностью удалённую до
введения журналов историю восстановить нельзя. Это ограничение исторических данных,
а не повод выдумывать порядок действий.

## Выкладка и проверки

Нужна миграция `scripts/migrations/20261122-series-achievements.sql` **до** приложения.
Единый пакет и проверки: `scripts/supabase/01-upgrade.sql`, `02-verify.sql`.
Рабочая БД автоматически не меняется; см. `scripts/supabase/README.md`.

Локальные проверки: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
Тесты охватывают четыре порога, уникальность старых фильмов, полный/неполный каталог,
размер сериала, оценки половинным шагом и передачу постоянных завершений в редкость.
