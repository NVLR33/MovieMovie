## Внесённые исправления

- Зависимости: исправлено конфликтующее dev-дерево esbuild/Drizzle Kit; точечный override вместо разрушительного `npm audit fix --force`. Чистый `npm ci`, `npm ls --all` и аудит проходят. Наличие новой версии само по себе не повод для массового обновления major-версий.
- Каталог: единый разбор URL-параметров и фильтрация; пересечение поиска, категории, жанра, студии, года, рейтинга, статуса просмотра и настроения; токены студий/жанров вместо ложных совпадений подстрок; четыре детерминированные сортировки без мутации исходного массива. Переход по ссылке с точными фильтрами раскрывает их панель.
- Страницы: allowlist путей и диапазон PostgreSQL integer ID; неизвестные/вложенные неверные пути и отсутствующие материалы/пользователи возвращают настоящий 404.
- API: ограниченный 64 KiB JSON-reader, проверка object JSON и ID, same-origin защита изменяющих запросов, разграничение 400/401/403/404/413/500; клиенту не выдаются SQL-запросы/внутренние ошибки БД.
- Социальные действия: нормализация ответов к корню обсуждения, удаление ветки отзывов, транзакционные реакции и обработка дружбы; рекомендации доступны только принятым друзьям; повторное принятие заявки не создаёт повторных уведомлений.
- Редактирование материала: обязательные поля, категории/годы/длительность/серии/ссылки; отсутствующий ID не выдаётся за успешное обновление; после сохранения обновляются данные приложения.
- Профили/сравнение: отмена устаревших загрузок, обработка ошибок вместо вечного spinner. Персональные ответы data/profile/chat/auth GET/wrapped явно `private, no-store`.
- OAuth: переход документом, таймауты внешних запросов, очистка state cookie при отмене; тела ответов с токенами не логируются.
- Проигрыватель: разрешены только нормализованные HTTPS embed URL YouTube/RuTube/VK; произвольные iframe запрещены, добавлены sandbox/referrer policy. Комната честно обозначена как локальный предпросмотр.
- Игры: безопасная работа с маленьким каталогом, уникальные варианты ответов, валидные вопросы, пять раундов и защита повторного завершения. Сервер принимает только известные режимы и целые результаты 0–5. **Клиентские результаты больше не начисляют XP**: иначе прямой повтор POST позволял бесконечно создавать опыт. История тренировок сохранена; тексты интерфейса приведены в соответствие с текущей механикой.
- Недоступные localStorage/clipboard больше не обрушивают оболочку приложения. Выбор страны получил доступное имя.
- Убраны параллельные query на одном транзакционном pg-клиенте при вычислении титулов — предупреждение о несовместимости с будущим pg устранено в этом месте.
- Добавлены регрессионные тесты и workflow `.github/workflows/quality.yml`. Сам workflow ещё не запускался на GitHub; соответствующие команды выполнены локально.

## Известные оставшиеся ограничения

1. **Совместный просмотр**: серверной синхронизации playback/участников и room-чата нет; сейчас это локальный предпросмотр, а не реализованный watch party. Embed также зависит от разрешений владельца видео и CSP провайдера.
2. **Игры**: результат по-прежнему рассчитывается в браузере и не является защищённым соревновательным результатом. Для возвращения XP нужны серверная выдача заданий, проверка ответов, одноразовая сессия и защита повторной отправки. Исторические XP не пересчитывались. Некоторые тематические режимы — варианты викторины, не самостоятельные Wordle/Connections-механики.
3. **Общие подборки**: `voteList` пока считает нажатия, а не уникальных голосовавших; нет user-vote ledger. Одновременные `addToList` также требуют уникального ограничения `(list_id, movie_id)` для полной защиты от гонки. Это отдельная миграционная задача, не путать с исправленным топом «По любимому», где считаются уникальные пользователи.
4. **Нагрузка/abuse**: полноценные распределённые rate limits, пагинация длинных историй чата и нагрузочные испытания не выполнены. Проверка размера upload по Content-Length/размеру файла не заменяет жёсткий streaming limit на reverse proxy.
5. **Production**: фактическое состояние Supabase, применение миграций, RLS/Storage policy в настоящем проекте, OAuth/Telegram end-to-end, SSE через hosting proxy и доступность внешних постеров/плееров нужно проверить после настройки окружения. `/api/health` проверяет подключение (`SELECT 1`), не полноту схемы; для неё используется `npm run db:verify`.

## Воспроизведение локальных HTTP/browser-проверок

Не запускать эти mutating suites на пользовательской или production-БД. Fixture server поднимает только изолированную in-memory PGlite и Unix socket `/tmp/mm-audit-pg/.s.PGSQL.5432`. Перед повторным полным HTTP-прогоном перезапустить fixture/server: suite изменяет данные.

```sh
npm ci
npm run typecheck && npm run lint && npm test
npm run test:wallet && npm run test:live
npm audit

# Необязательные инструменты — вне репозитория.
npm install --prefix /tmp/mm-audit-tools @electric-sql/pglite-socket@0.2.20 playwright-core@1.65.1 @sparticuz/chromium@153.0.0
export AUDIT_DB_DEPS=/tmp/mm-audit-tools UI_TEST_DEPS=/tmp/mm-audit-tools
export DATABASE_URL='postgresql://postgres:postgres@localhost/app_db?host=/tmp/mm-audit-pg'
export AUDIT_DATABASE_URL="$DATABASE_URL"
export SESSION_SECRET='isolated-local-session-secret-not-for-production'
export AWS_EXECUTION_ENV=AWS_Lambda_nodejs22.x

# Отдельный терминал, с теми же переменными:
node tests/integration/serve-audit-db.mjs

# Ещё один терминал:
npm run build
npm start -- --hostname 0.0.0.0 --port 3000

# После запуска сервера:
node tests/integration/wait-for-audit.mjs
npm run test:routes
npm run test:browser
npm run test:ui
```

Крупные зависимости браузера, screenshots и временные БД в Git не добавлены.
