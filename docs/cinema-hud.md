# Cinema HUD — личный командный центр

HUD развивает кинематографичный интерфейс, не заменяя его игровым меню. Логотип,
нижняя мобильная навигация, темы, цвета рейтингов и Ambient Canvas сохранены.

## Что изменилось

- В шапке авторизованного пользователя — тонкая сегментированная XP-шкала и
  кнопка `LVL`, открывающая профиль. На телефоне кнопка расположена рядом с поиском,
  чтобы не вытеснять логотип и меню аккаунта. На широком экране виден общий XP.
- Цифровой счётчик за 700 ms переходит от предыдущего отображаемого значения к
  новому, а не стартует с нуля после каждого запроса. Начальная загрузка не выдаётся
  за получение награды.
- При росте XP показывается ненавязчивое сообщение `+N XP`. При пересечении уровня
  полоса заполняется до края, сбрасывается и заполняет новый уровень; сообщение
  отмечает новый уровень. Отрицательная коррекция оформляется без празднования.
- В личном профиле — командный центр: уровень/XP, уникальные просмотренные истории,
  время по дневнику, число открытых достижений (включая скрытые), активные дни по UTC.
  Название зрителя по-прежнему зависит от числа просмотренных историй, не от XP.
- Блок «Ближайшая цель» выбирает следующий неоткрытый тир реального достижения
  с наибольшей долей выполнения. Есть описание, текущий счётчик, цель, тир и переход
  в достижения. Это не новое задание и не дополнительная XP-награда. При полном
  выполнении всех обычных тиров предлагается исследовать скрытые трофеи.
- Основные блоки дневника собраны в 12-колоночный Bento: статистика 8/12, категории
  4/12, история 7/12, достижения 5/12, друзья на всю ширину. На промежуточных
  экранах сетка упрощается, на телефонах становится одноколоночной. DOM-порядок
  остаётся сохранённым порядком пользователя — без CSS dense и визуальной перестановки.
- Внутри статистики — вторичная асимметричная сетка. Обложка личного профиля
  компактнее, имя заметнее, превью достижений читабельнее в узкой плитке.

## Реальные данные вместо фиктивного прогресса

Правила начислений не изменены: сервер остаётся единственным источником XP.
Уровень = `floor(max(0, XP) / 500) + 1`, полоса показывает остаток от деления на 500.
Первый просмотр материала даёт +35 XP, отмена возвращает 35 XP; первая оценка +10 XP,
редактирование оценки не даёт ещё +10. Желаемое и любимое XP не начисляют.

HUD берёт XP из подтверждённого `/api/data`, а не оптимистичного нажатия кнопки.
Ошибка запроса не создаёт ложную награду. Компонент шапки привязан ключом к ID
пользователя, поэтому смена аккаунта не выглядит как получение XP. Повторная загрузка
того же значения не перезапускает награду. Разница снимков может включать несколько
действий/изменения из другой вкладки: интерфейс не приписывает её одному конкретному
действию. Никаких клиентских запросов на «выдать XP» нет.

## Загрузка, производительность и доступность

`data-hud-busy` считает активные общие refresh и action-запросы. Пульсация тонкой рамки
есть только пока запрос действительно выполняется, включая подтверждающую загрузку
после мутации. На фоне SSE-подключения и в простое рамки не анимируются. Сам пульс
медленный (1,8 s), меняет только непрозрачность декоративного контура и не блокирует
содержимое. Отдельный публичный `/api/pulse` не выдаётся за загрузку личной статистики.

Счётчик меняет только один DOM-текст через requestAnimationFrame — не перерисовывает
всё приложение каждый кадр. Числа используют tabular numerals. Декоративные сетка и
свечение созданы CSS, без изображений, новой библиотеки или постоянного GPU-слоя.

Обе XP-полосы имеют progressbar-семантику, подпись и точные ARIA-значения; анимированный
текст скрыт от скринридера, доступные значения всегда актуальны. Награды объявляются
через polite live region, без перехвата фокуса. Кнопки HUD минимум 44 px.
При `prefers-reduced-motion` счётчик и полоса обновляются мгновенно, вместо пульса
остаётся статическая рамка. Сообщение о XP скрывается без движения. Forced-colors
сохраняет видимую полосу прогресса. Цвета берутся из текущих theme/ambient токенов,
поэтому HUD поддерживает светлую тему и палитру постера.

## Файлы и проверки

- `src/lib/hud-progress.ts`: нормализация XP, уровень, ближайшая цель.
- `src/components/cinema-hud.tsx` / `.css`: шапка и командный центр.
- `tests/hud-progress.test.ts`: границы 499/500, отсутствующие и некорректные данные,
  понижение XP, выбор следующего тира и полностью собранная коллекция.
- `npm run test:hud:browser`: production Next + настоящие API и изолированная БД;
  +35/-35, +10 за первую оценку и +0 за редактирование, переход уровня, отсутствие
  фиктивного XP при ошибке/закладке, загрузка рамок, reduced motion, темы, гостевой
  режим, целевые переходы и 8 ширин 320–1920. Скриншоты в `/tmp/mm-hud-screenshots`.
- `npm run test:ui`: общий адаптивный fixture-тест приложения также включает HUD CSS.

Браузерный тест использует те же `UI_TEST_DEPS`, `AUDIT_DATABASE_URL`,
`AUDIT_BASE_URL`, `AWS_EXECUTION_ENV` и локальную тестовую БД, что мобильный аудит.
Обязательны Unix-сокет `/tmp/mm-audit-pg`, loopback web host и DB-маркер
`mm_audit_fixture.isolated=yes`. Созданные тестовые аккаунты остаются только в памяти
этой одноразовой БД до остановки тестового сервера. Тест включён в CI.

Миграции, production-БД и инфраструктура для внедрения не нужны.
