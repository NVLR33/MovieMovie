# Уведомления и меню пользователя

Панели шапки переработаны в `HeaderAccount`. Общая структура сайта, настройки, авторизация, профиль, роли и система уровней сохраняются. Новых таблиц, зависимостей и миграций нет.

## Уведомления

- Колокольчик имеет доступное имя и числовой счётчик **непрочитанных** (99+ для больших значений); навязчивое потряхивание отключено.
- Открытие панели больше **не вызывает notifyRead**. Прочтение — явное действие: клик по событию/галочке либо «Прочитать всё».
- Все/непрочитанные, поиск по тексту, группы сегодня/вчера/ранее, относительное время с полной датой в title, новые/прочитанные строки и отдельные визуальные типы событий.
- У исторических записей нет поля типа; иконка определяется best-effort по сообщению/существующей ссылке. Это исключительно оформление: тип не определяет права или доступ.
- Показ первых 20 записей и «Показать ещё» по 20 вместо прежней скрытой обрезки до восьми. Это **постепенный рендер уже полученного списка**, не серверная cursor-пагинация; `/api/data` по-прежнему отдаёт список владельца.
- Отдельную запись можно вернуть в непрочитанные. Операции блокируются от повторного нажатия до завершения, ошибки остаются видимыми с возможностью повторить; неудачное изменение не выдаётся за успех.
- При открытии события непрочитанная запись сначала отмечается прочитанной; при ошибке остаёмся в панели. При успехе переходим по существующей ссылке. Внешние/неизвестные/scheme-relative/управляющие символы в сохранённых ссылках не допускаются (`noticeHref`). Для таких записей доступны текст и переключение состояния без опасного перехода.
- Гостю — объяснение и вход, для пустого списка/пустого фильтра/безрезультатного поиска — отдельные состояния. Ни новых наград, ни XP за чтение нет.

### API и приватность

Прежний `POST /api/action` с `action: notifyRead` без id сохраняет совместимый явный режим «прочитать всё».

`{action:'notifyRead', id, read?:boolean}` меняет только запись с **id и userId текущей сессии**. По умолчанию read=true; read=false допустим только для конкретной записи. Строковые/неверные read, некорректные id и попытки изменения чужого/несуществующего уведомления отклоняются (400/404, без раскрытия владельца). Гостю 401. Сохраняются same-origin/session проверки. Данные/сообщения не попадают в публичный pulse; прежние приватные SSE-инвалидации/refresh продолжают работать.

## Меню аккаунта

- Аватар/имя, email и роль, настоящий уровень и прогресс до следующего уровня через существующий `experienceProgress` (500 XP на уровень).
- Профиль, буду смотреть и любимое с реальными числами, друзья, достижения, подборки, настройки сайта. Нет выдуманных счётчиков или новых прав.
- Центр управления виден только по существующему `canAccessAdmin`, включая независимую capability редактора; ограничения серверных маршрутов не меняются.
- Настройки открывают тот же компонент `SiteSettings` через явную ссылку на его trigger, без дублирования форм и вложенных модальных окон.
- Выход проверяет HTTP-успех и предотвращает повторную отправку. При ошибке сессия/панель остаются на месте и показана ошибка. После успешного выхода приватный клиентский snapshot очищается до фонового refresh. При незавершённом изменении коллекции выход просит повторить, не теряя изменение.

## Адаптивность и доступность

Обе панели — native dialog в top layer через portal; фон под ними не мешает чтению. На десктопе панель привязана к кнопке, на телефоне располагается внизу с учётом доступной высоты/safe-area. Внутри собственная прокрутка. Нет выпадающего списка, обрезанного шапкой или viewport.

Открыта только одна панель, Escape/кнопка/клик снаружи закрывают её; Tab/Shift+Tab остаются внутри, фокус возвращается на trigger и снимается блокировка прокрутки страницы. Ссылки профиля поддерживают обычную навигацию и модификаторы для новой вкладки. Это dialog с обычной клавиатурной навигацией, не псевдо-menu без реализации стрелок. Имена кнопок, расширенность, статус, активные фильтры и ошибки доступны скринридеру. Русские/английские подписи, светлая/тёмная темы и reduced-motion сохранены.
