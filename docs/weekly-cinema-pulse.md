# Недельный Кинопульс

## Формат

На главной вместо четырёх старых разнотипных карточек теперь единый недельный чарт:
первые три места — крупные карточки с постером, описанием, годом/типом/длительностью,
общим рейтингом и числом недельных зрителей. Места 4–10 — компактный постерный ряд.
Есть возрастное ограничение, если оно заполнено в каталоге. Длинные описания
ограничены строками; полный текст доступен при переходе на материал.

Все десять материалов имеют отдельную кнопку «Смотреть позже»; лидеры дополнительно
дают «Отметить просмотр» и ссылку «Открыть и оценить». Это ссылка на материал с
существующими средствами оценки, не отдельная форма или выдуманная быстрая оценка.
Нет вложенных интерактивных элементов в ссылках и кнопках. Ссылки поддерживают
Ctrl/Cmd-click, кнопки подписаны названием материала, доступны с клавиатуры.

В широком layout три лидера сверху и семь постеров снизу. На планшете первый лидер
занимает всю строку, второй/третий идут рядом; на телефоне лидеры выстроены
вертикально, остаток прокручивается локально свайпом/клавиатурой. Колесо страницы
не перехватывается. Автопрокрутки нет. Цвета используют токены сайта,
светлая тема имеет контрастные подписи мест. Пустые/неудачно загруженные постеры
получают нейтральную иконку, но не теряют название и ссылку.

## Настоящая неделя вместо рейтинга за всё время

Старый блок «На этой неделе» фактически выбирал лучший/худший общий рейтинг и год
выпуска. Теперь данные действительно ограничены **последними 7 × 24 часами** на
момент запроса, а не календарной неделей с понедельника. Интервал отображается с
подписью UTC, методика пояснена непосредственно над/под чартом.

Метрика: число уникальных userId, имеющих текущую отметку просмотра данного
материала с watchedAt внутри включительного диапазона [now − 7 дней, now].

- Повторные записи одного зрителя внутри материала не удваивают результат.
- Будущие, невалидные и более старые даты не учитываются.
- Материалы без активности не подмешиваются для заполнения десятки.
- Это не посещения страниц, не часы, не сеансы стриминга, не число оценок и не
  недельный средний рейтинг. Звёздочкой показывается обычный общий рейтинг сайта,
  без голосов он отображается прочерком.
- Ничья: выше общий рейтинг с реальными голосами, затем число оценок и ID.
- Список ограничен десятью уникальными материалами. В малой неделе показываются
  только реальные позиции, а при отсутствии активности — объяснение и каталог.
  Начальное отсутствие полученного снимка отличается от подтверждённой пустой недели.
- Модель повторных сеансов не вводилась. Удаление отметки просмотра может убрать
  зрителя из чарта. Исторические удаления не архивируются.

## API и обновление

`src/lib/weekly-pulse.ts` содержит общие типы/ранжирование и чистый сборщик из
имеющихся отметок. `/api/data` рассчитывает `weeklyPulse` из уже загруженных
allWatches. `/api/pulse` делает группирующий запрос count(distinct user_id) по
семидневному диапазону, затем использует тот же ранжировщик.

Общедоступный weeklyPulse содержит только since/until и entries [{movieId,viewers}].
Никакие ID зрителей или их личные истории для чарта наружу не добавляются.
Общедоступная тройка лидеров пользователей остаётся отдельным прежним показателем,
не заменяется и не смешивается с топом материалов.

Существующий SSE и коалесцированное обновление `/api/pulse` передают weeklyPulse
вместе с films/weeklyLeaders. Дополнительного EventSource/WS, периодического опроса
или соединения на каждую карточку нет. В спокойном открытом окне показан последний
полученный снимок с периодом, а не обещание пересчёта каждую секунду; изменение
активности, обновление страницы или штатный resync обновляют диапазон и чарт.

Действия используют прежний общий action/optimistic-store: ошибка сохранения
откатывает кнопку, успешный ответ синхронизирует серверные данные и XP. Отдельного
клиентского счётчика XP нет. На время запроса повторное действие отключено; гостю
открывается существующая авторизация. Кнопка просмотренного лидера остаётся
подтверждённой и отключённой, чтобы повторный клик не удалял просмотр/XP. Управление
удалением по-прежнему доступно в обычных разделах сайта. Просмотр может изменить
порядок чарта после ответа сервера — это реальная активность, а не оптимистически
сфабрикованная позиция.

## Файлы и проверки

- `src/components/weekly-cinema-pulse.tsx` / `.css` — витрина и контролы.
- `src/lib/weekly-pulse.ts` — период, группировка и общий ранжировщик.
- `tests/weekly-pulse.test.ts` — уникальные зрители, обе границы диапазона,
  old/future/invalid исключения, orphan ID, ничьи/неоценённые, top10/privacy/пустота.
- `npm run test:pulse:browser`: production Next и одноразовая marker-guarded SQL,
  loopback URL и сокет `/tmp/mm-audit-pg`. Создаёт настоящие отметки 25 фикстурных
  зрителей для десяти текущих материалов и отдельных старого/будущего. Сверяет
  публичный и общий API, отсутствие личных данных в entries, раскладку 3+7, откат
  сохранения/его persistence, просмотр и публичное SSE-обновление второй страницы,
  гостевой вход, переход к материалу, две темы/восемь ширин, клавиатурный скролл,
  малый/пустой снимки. Фильмовые фикстуры/связи удаляются в finally, тестовые аккаунты
  без паролей остаются только в одноразовой БД из-за связанных событий/уведомлений.
- Скриншоты: `/tmp/mm-weekly-pulse-screenshots/pulse-{dark,light,mobile}.png`.
- `test:ui` включает CSS чарта и fixture weeklyPulse, сохраняет проверки адаптива,
  единого SSE, частичного public refresh, optimistic и прочих разделов.
- Новый browser-тест включён в CI после `test:showcase:browser` с теми же
  AUDIT_DATABASE_URL / UI_TEST_DEPS / AWS_EXECUTION_ENV.

Новых зависимостей, таблиц и миграций нет. Production-БД и деплой не менялись.

Рейтинговые рамки и необязательный hover-трейлер не меняют структуру 3 + 7.
См. [карточки](visual-design-system.md) и [трейлеры](trailers.md).
