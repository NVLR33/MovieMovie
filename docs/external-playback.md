# Внешний просмотр материалов

## Возможности и границы

MovieMovie хранит **только URL**, не скачивает, не проксирует и не раздаёт видеопоток. Автоматического поиска фильмов, извлечения скрытых ссылок, обхода авторизации, DRM, рекламы или запретов встраивания нет. HLS/WebM/YouTube не входят в первую версию **полного просмотра**; существующие возможности трейлеров не меняются.

Поддержаны:

- VK Видео: `https://vkvideo.ru/video-OWNER_ID_VIDEO_ID` / `https://vk.com/video...` и официальный `video_ext.php?oid=...&id=...` (не HTML-код). Источник приводится к `https://vk.com/video_ext.php`; допустимый share hash сохраняется.
- Rutube: обычная ссылка `/video/<32-hex-id>/` или `/play/embed/<id>/`. Допустимый параметр доступа `p` сохраняется.
- Прямая HTTPS-ссылка с `.mp4` в pathname, в том числе с query. Нужны поддерживаемые браузером кодеки/Content-Type; для перемотки источник должен корректно отдавать byte ranges. Расширение само по себе не доказывает работоспособность видео.

Только свой контент или контент с разрешением на такое использование. Доступность, возрастные/региональные ограничения, реклама, cookies и возможность embedding определяются владельцем источника. Наличие ссылки не предоставляет прав на показ.

Ссылки видны посетителям. **Не добавлять пароли, API-ключи, персональные ссылки и секретные токены.** Временные подписанные ссылки могут истечь. Проверка адреса не проверяет лицензию, содержимое файла, DNS/редиректы, доступность или разрешение embedding; публиковать источники должны доверенные редакторы.

## Работа редактора

1. В форме материала заполнить **«Источник просмотра на сайте»**. Форма показывает распознанного провайдера или подсказку об ошибке; сервер повторно проверяет URL.
2. Сохранить материал. Создание доступно по прежнему праву редактора; изменение опубликованного материала — администратору/модератору. Предложения проходят общую валидацию и модерацию.
3. Для сериала: **«Редактировать сезоны» → источник просмотра эпизода → «Сохранить эпизод»**. У каждого эпизода независимая ссылка; сервер проверяет принадлежность эпизода сериалу. Пустая строка удаляет источник.

Поля независимы:

| Поле | Назначение |
|---|---|
| `trailer_url` | Короткий трейлер и существующее hover-превью |
| `watch_url` | Прежняя внешняя кнопка «Где посмотреть» |
| `playback_url` | Просмотр фильма/эпизода в диалоге MovieMovie |

Никаких автоматических преобразований старой `watch_url` в источник просмотра не производится. Старый API-клиент, не передавший `playbackUrl` при редактировании, не стирает существующий источник.

## Зритель и приватность

Кнопка **«Смотреть»** открывает native dialog с информацией об источнике. До нажатия **«Подключить …»** в DOM нет видео/iframe с этим источником и приложение не обращается к нему. Согласие не запоминается между открытиями. До подключения останавливается активное/ожидающее превью трейлера.

После согласия браузер зрителя подключается напрямую к источнику: тот получает IP и может применять свои cookies/аналитику. Плеер не получает `autoplay` от приложения; MP4 использует `controls`, `playsInline`, `preload=none`. Iframe разрешён только для известных провайдеров, с `sandbox`, без top-navigation/popups, с `referrerPolicy=no-referrer`. Недоступные при таком sandbox функции провайдера не обходятся ослаблением защиты.

Закрытие/Escape, уход со страницы или «Отключить источник» удаляют видео/iframe; фокус возвращается кнопке, прокрутка страницы восстанавливается. Ошибка MP4 даёт сообщение и повтор. Ссылка **«Открыть у источника»** доступна всегда: запрет embedding, рекламу и HTTP-ошибку внутри чужого iframe надёжно определить из нашего JS нельзя.

Просмотр не ставит отметку «Просмотрено», не меняет оценки, прогресс достижений и XP. Изменение только названия/источника эпизода не сбрасывает подтверждённую полноту списка сезонов. Полнота сбрасывается при изменении состава сезонов/эпизодов.

## Выкладка

Подготовлена аддитивная миграция `scripts/migrations/20261122-zzzzzz-playback.sql`: две текстовые колонки `playback_url NOT NULL DEFAULT ''` в `mg_movies` и `mg_series_episodes`. Обновлены SQL bundle, структурный аудит и контроль инвентаря миграций. Новый bucket, загрузки файлов, внешние ключи/аккаунты провайдеров и сервис видеопрокси не нужны.

**На production ничего не применялось.** Перед выкладкой: backup/снимок БД → штатная миграция через CLI или обновлённый Supabase bundle → обе проверки схемы → приложение → ручная проверка разрешённого видео каждого нужного провайдера на реальных устройствах и сети пользователей.

До миграции каталог и список эпизодов читаются через совместимый JSON-lookup и показывают пустой источник; запись материалов/редакторские изменения эпизодов отвечают понятным 503 с именем миграции. Runtime-DDL и молчаливого удаления ссылок нет. Миграция проверена **только в изолированной тестовой БД**.

Если позже появится CSP, в `frame-src` потребуются `https://vk.com` и `https://rutube.ru`; в `media-src` — одобренные домены MP4. Сервер не проверяет внешние ссылки сетевыми запросами.

## Проверки

- 268 unit-тестов, typecheck, lint и production build.
- `test:playback:browser`: API roundtrip фильма/эпизода; права, нормализация и отказ для неверных адресов; поле редактора; отсутствие обращений к провайдеру до согласия; sandbox/referrer-policy; закрытие/отключение/фокус; MP4 без autoplay, ошибка/повтор/fallback; четыре ширины; отсутствие автотрекинга; чтение до миграции и безопасный отказ записи. Внешние запросы перехвачены фикстурой — **доступность реального VK/Rutube/MP4 этим тестом не подтверждается**.
- Регрессии навигации сезонов, дизайна/hover-трейлеров, предложений и совместимости trailer-схемы.
- Изолированные wallet/migration, realtime/storage, suggestions, admin, auth integration suites.
- Новый browser suite включён в quality workflow; удалённый CI не запускался в этой задаче.
