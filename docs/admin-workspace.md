# Центр управления MovieMovie

Панель доступна по `/admin`. Вкладки сохраняются в URL (`?tab=users`, `?tab=suggestions` и т. д.), поэтому работают прямые ссылки и история браузера.

## Права

| Возможность | Администратор | Модератор | Посетитель / VIP + «Редактор» |
| --- | --- | --- | --- |
| Добавление нового материала, загрузка постера/фона | Да | Да | Да |
| Редактирование существующих карточек, сезонов и серий | Да | Да | Нет |
| Одобрение / отклонение предложений | Да | Да | Нет |
| Общая модерация комментариев | Да | Да | Нет |
| Удаление материала и связанных записей | Да | Нет | Нет |
| Витрина и фильм недели киноклуба | Да | Нет | Нет |
| Поиск аккаунтов, email, роли, редакторы | Да | Нет | Нет |
| Блокировка / разблокировка, отзыв сессий | Да | Нет | Нет |
| Просмотр журнала действий | Да | Нет | Нет |

**«Редактор» — независимый boolean `isEditor`, а не новая роль.** Галочку можно назначить пользователю любой основной роли. Для администратора и модератора добавление материалов уже входит в роль; снятие дополнительной галочки не отнимает их штатные возможности. Обычный редактор публикует напрямую через общую полноценную форму; это не предложка. Галочка не даёт возможности редактировать чужие/существующие карточки, пользователей, витрину или сезоны. Авторство/владение карточками в текущей модели не вводится.

Роль и право редактора проверяются на сервере, включая `/api/action`, `/api/admin`, `/api/upload` и `/api/series`. Скрытые кнопки не являются защитой. Роли не записываются в JWT: каждое обращение читает актуальный аккаунт из БД.

## Разделы

- **Обзор:** фактические SQL-показатели каталога, витрины, неполных карточек; для команды — очередь, участники, новые регистрации и просмотры за последние 7 дней, комментарии; только администратору — число редакторов и блокировок. «Просмотры за 7 дней» — записи истории просмотра, не посещения страниц.
- **Материалы:** поиск по названию / оригинальному названию / ID, категории, витрина, неполные карточки, сортировка по дате добавления / названию / посещениям, страницы по 25. Неполной считается карточка без описания, постера, жанра или страны. Администратор может выбрать до 50 карточек и массово включить/выключить витрину. Удаление требует подтверждения и не имеет отмены.
- **Предложения:** полноценная очередь с проверкой, правками, причинами отказа и архивом, см. `movie-suggestions.md`.
- **Комментарии:** серверный поиск по тексту, автору, названию материала; фильтры ответов и спойлеров; изменение отметки спойлера и удаление ветки с причиной. При удалении чужого комментария причина обязательна и на сервере; автору отправляется уведомление. Модератор видит полный текст спойлеров намеренно.
- **Пользователи и роли:** серверная пагинация по 25, поиск имени / email / ID, фильтры ролей, редакторов и блокировок, сортировка; счётчики просмотров и комментариев, дата регистрации. Email, причина блокировки и управление аккаунтами доступны только администратору.
- **Журнал действий:** серверная пагинация, поиск по исполнителю / описанию и фильтр типа действия; время, исполнитель, объект, разрешённые подробности изменения. Экран не имеет инструментов изменения/очистки журнала.

При назначении фильма недели предыдущие записи киноклуба деактивируются, история сохраняется. Неделя начинается в понедельник по UTC. При повторном выборе создаётся новая историческая запись; активной остаётся одна. Массовые операции с витриной атомарны: если хотя бы одной карточки уже нет, вся операция отклоняется.

## Защита аккаунтов и сессий

- Нельзя менять собственные роль/галочку, блокировать себя или отзывать свои сессии через административные команды. Обычный выход работает отдельно. Это защищает текущего администратора от случайного самоограничения.
- Администратора нельзя заблокировать: сначала другой администратор должен явно понизить его роль. Заблокированного пользователя нельзя назначить администратором до разблокировки.
- Блокировка требует непустой причины до 500 символов. Все блокировки и разблокировки увеличивают `sessionVersion`; старые cookie больше не действуют. Вход заблокированного аккаунта отклоняется для всех провайдеров через общий `setSession`.
- Отзыв сессий и смена роли также увеличивают `sessionVersion`. Пользователь должен заново войти на всех устройствах. Разблокировка не восстанавливает старые сессии.
- Старые cookie без версии принимаются только для аккаунтов с версией 0. Выдача/отзыв галочки редактора не завершает сессии, но действует со следующего запроса благодаря DB-проверкам.
- При отказе сессии интерфейс считает пользователя гостем; публичный просмотр сайта остаётся доступным.
- Версия сессии и причина блокировки исключены из обычного `publicUser`; общий список участников и публичный профиль используют явный whitelist и не раскрывают новые приватные поля.

Административные изменения аккаунтов сериализованы advisory lock и row locks; полномочия инициатора повторно проверяются в транзакции. Изменения каталога и их журнал выполняются в одной транзакции. Запись журнала содержит только явно заданные данные: без паролей, токенов, provider ID, тел комментариев и личных сообщений. Удаление материала не удаляет его исторический журнал. БД-таблица журнала с RLS, без публичных политик и с отозванными правами `PUBLIC` / `anon` / `authenticated`. Серверному DB-пользователю нужны прежние полномочия владельца / bypass RLS.

**Границы:** запрос, который уже прошёл авторизацию до отзыва прав, не обязательно отменяется; это не распределённый interrupt всех выполняющихся операций. Пароли, DNS, секреты, SQL-консоль, массовое удаление аккаунтов, ручная накрутка XP/кошелька намеренно не вынесены в админку. Отдельных жалоб/тикетов и автосканирования контента пока нет. Старая операция удаления комментария автором собственного сообщения не считается административной и не журналируется.

## Миграция перед выкладкой

Добавлена **11-я миграция** `scripts/migrations/20261122-zzzz-admin-workspace.sql`:

- `mg_users.is_editor`, `is_suspended`, `suspension_reason`, `session_version`;
- приватная `mg_admin_audit` с индексами по исполнителю/действию и времени.

Итого: **32 таблицы, 228 столбцов, 11 миграций**. Данные не удаляются; существующие роли сохранены, новые флаги по умолчанию выключены. Старые миграции не изменялись. `npm run db:bundle` регенерирует общий SQL и структурный audit.

1. Сделать резервную копию рабочей БД.
2. Применить целиком обновлённый `scripts/supabase/01-upgrade.sql` в Supabase SQL Editor либо выполнить `npm run db:migrate` в корректном серверном окружении. Не запускать `setup-db` на рабочей базе.
3. Выполнить `02-verify.sql`, `03-schema-audit.sql` / `npm run db:verify`.
4. **Только после миграции** выкладывать код. Обычный push не обновляет БД автоматически.
5. Проверить рабочий админский аккаунт, выдачу редактора и реальную Storage-загрузку на опубликованном сайте.

В этой работе production БД, DNS, Storage и хостинг не изменялись.

## Проверки

- `npm test` — в том числе матрица всех ролей × флаг редактора, запрет прав заблокированным и совместимость / отзыв версий сессий.
- `npm run test:admin` — реальные реализации route + PGlite, 71 запрос: разграничение прав, редактор любой роли, self/admin-защита, фильтры/пагинация, приватность HTTP и RLS/ACL таблицы журнала, витрина, киноклуб, модерация, версии сессий и принудительный сбой журнала с проверкой rollback.
- `npm run test:admin:browser` — production Next + Chromium: шесть вкладок на 320/390/768/1440 px, выдача галочки, диалоги, блокировка и отказ во входе, разблокировка без оживления cookie, отзыв сессий, выход при смене роли, ограниченная панель модератора и журнал. Только локальная marker-защищённая fixture; окружение аналогично `test:suggestions:browser`.
- `test:suggestions`, `test:wallet`, `test:live`, `test:routes`, `test:browser`, `test:ui` — регрессии предложки, миграций, кошелька, SSE, API и основного интерфейса.
