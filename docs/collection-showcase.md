# Кинематографичные подборки

## Витрины вместо закрытого экрана списков

`/collab` теперь общедоступная страница киноподборок. Навигационный пункт «Подборки»
сохранён. Виды: все, студии, актёры, жанры, совместные. URL вида
`/collab?view=studio` сохраняет выбранный вид; старый `/collab` открывает обзор.

Каждая витрина: широкая фоновая сцена, иконка типа подборки (не вымышленный логотип
правообладателя), название, пояснение, реальное число материалов, отметки просмотра,
горизонтальный ряд до восьми постеров и «Смотреть все». Если доступен настоящий
`backdrop` одного из материалов, он используется с тёмными градиентами для
читаемости. Если фона нет или загрузка не удалась, остаётся аккуратный градиент,
без растягивания постера. Сами витрины намеренно кинематографично-тёмные в обеих
темах, остальная страница использует обычные токены светлой/тёмной темы.

Подборки не заявляются официальными рекомендациями студии или актёра. Это явно
указано на странице. Не вводятся вымышленные рекомендации «для вас», официальные
партнёрства, актёры/студии, отсутствующие в каталоге, или случайные картинки извне.

## Реальные связи

`src/lib/collection-showcase.ts` группирует уникальные movieId по полям:

- `studio` — студии, указанные в каталоге;
- `cast` — актёрский состав, а не режиссёр или совпадение имени в описании;
- `genre` — точные жанровые токены.

Разделители: запятая, точка с запятой, перенос строки (`splitCinemaNames`). Имена
нормализуются по регистру, пробелам, Unicode NFKC и ё/е. Повтор одного имени внутри
материала не удваивает его; дубликаты movieId не создают повторные постеры. Пустые
и явные неизвестные значения пропускаются. A24 не совпадает с A240. Не пытаемся
автоматически сопоставлять псевдонимы, переводы и альтернативные написания имени:
для этого каталог должен быть заполнен единообразно.

Порядок витрин — по числу материалов, затем по имени/ключу. Внутри: сначала реально
оценённые материалы, затем средняя оценка, посещения, год и ID. Нет ложного среднего
рейтинга всей подборки. Материалы без оценок показывают прочерк. Рейтинг каждой
карточки — оценка зрителей сайта. Просмотрено — пересечение текущих личных отметок
с точным составом; гостям не показывается вымышленный личный прогресс.

## Поиск, полный состав, доступность

- Поиск по названию студии, актёра или жанра; вид и поиск работают совместно.
- Первые шесть витрин, следующие порциями по шесть. Это ограничение DOM, а не новая
  серверная пагинация: исходный каталог по-прежнему приходит из существующего API.
- «Смотреть все» открывает точную группу через `collection` в URL, а не нечёткий
  поиск по всему каталогу. Пример: `/collab?view=studio&collection=studio%3Aa24`.
- Полный состав — сетка с первыми 24 карточками и кнопкой следующей порции по 24.
  Обновление страницы и прямые ссылки работают; исчезнувшая группа получает
  пояснение и ссылку назад, не подменяется случайной подборкой.
- Ссылки постеров ведут на материалы, Ctrl/Cmd-click сохраняет обычное поведение.
  Постеры ленивые; при ошибке изображения остаются название/ссылка/нейтральная иконка.
- Ленты имеют локальную горизонтальную прокрутку, scroll-snap proximity, кнопки по
  44px, клавиатурный фокус; колесо/вертикальный скролл страницы не перехватываются.
  Автопрокрутки и таймеров нет. Reduced-motion отключает hover-сдвиг и плавный
  скролл стрелками. Forced-colors сохраняет различимость контента.
- На телефонах фон сохраняется, заголовки переносятся, в деталях сетка в две колонки.

## Совместные списки сохранены и доработаны

Вкладка `/collab?view=personal` оставляет вход обязательным, как раньше. Эти списки
**общие для участников сайта, не приватные**; это прямо пояснено. Серверные права и
модель хранения не изменялись. Используются прежние API createList/addToList/voteList.

Новый `collaborative-collections.tsx` даёт доступное создание списка, поиск по
каталогу и выбор материала для добавления (до 30 подходящих вариантов, уже добавленные
скрыты). Отсутствовавший раньше UI добавления теперь есть. Название/выбор очищаются
только после успешного ответа. На время сохранения отключён повторный submit,
голосование блокируется до ответа. Название материала открывает его страницу.
Ошибки показывает существующая система уведомлений. Новая уникальность голосов или
правила их начисления не заявляются: серверная механика голосов не менялась.
Ненужных кнопок удаления/редактирования без серверной поддержки нет.

## Файлы и проверки

- `src/lib/collection-showcase.ts` — чистые группы/фильтры/ссылки.
- `src/components/collection-showcase.tsx` / `.css` — обзор, витрина и полный состав.
- `src/components/collaborative-collections.tsx` — совместные списки.
- `tests/collection-showcase.test.ts` — нормализация, дубликаты, точные токены,
  отсутствие метаданных, порядок, фильтры, безопасные Unicode deep links.
- `npm run test:showcase:browser` — production Next + одноразовая БД только на
  loopback и `/tmp/mm-audit-pg`, с обязательным маркером изоляции. 26 фикстур,
  витрины/точные списки, прогресс, поиск/пустой результат, отсутствующая подборка,
  стрелки, клавиатура, постеры, общедоступность/авторизация совместных, отказ создания
  с сохранением черновика, настоящее создание/добавление/голос и обе темы.
  Скриншоты `/tmp/mm-showcase-screenshots`. Фикстуры удаляются в finally.
- `test:ui` включает новый CSS и прежние проверки реальной оболочки. Production
  browser-тест включён в CI после `test:rankings:browser` с общими переменными
  AUDIT_DATABASE_URL/UI_TEST_DEPS/AWS_EXECUTION_ENV.

Новых runtime-зависимостей, API и миграций нет. Production-БД не изменялась.
