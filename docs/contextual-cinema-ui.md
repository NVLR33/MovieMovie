# Контекстный каталог и микро-взаимодействия

## Настроения вместо постоянной панели фильтров

В каталоге горизонтальная прокручиваемая строка настроений: попкорновый аттракцион,
головоломки, поплакать, эстетика ночи, уютный вечер, на одном дыхании. «Уютный вечер»
сохраняет пользу уже существующего редакторского тега `cozy`.

Выбор фильтрует загруженный каталог сразу, без сети. Здесь намеренно не используется
`useOptimistic`: нечего подтверждать сервером или откатывать. Настроение пересекается
с поиском, категорией и точными фильтрами. Число результатов и пустое состояние
со сбросом отражают все ограничения, включая статус просмотра.

`src/lib/catalog-moods.ts` — единый набор названий и правил. Приоритет — тег `mood`
редактора; если он пуст, используется жанровая эвристика. Описание фильма не
сканируется для выдумывания настроения. Это не AI-рекомендации и не гарантированная
эмоциональная классификация: результат зависит от качества редакторских данных.
Старые `cry`, `mind-blowing`, `fast-paced`, `cozy` поддерживаются без переноса БД.
Редактор материалов предлагает те же настроения и сохраняет существующие значения.

Точные фильтры не удалены: кнопка «Все фильтры», счётчик активных ограничений.
Переход из достижения по ссылке с `year`/`genre`/`studio` автоматически открывает
панель. Сохранены категории и сортировки. Для настроений поддерживается входная
ссылка `/catalog?mood=night`; клики на теги не засоряют историю браузера.

## Шторка отзывов

В карточке материала — «Мнения сообщества», ниже вместо длинной ленты — компактный
вход в обсуждение. Сама лента перенесена, не продублирована. Отзывы, ответы, реакции,
редактирование, удаление, права модератора и спойлеры используют прежние API.

`ReviewDrawer` использует нативный модальный `<dialog>` в портале `document.body`:
правый край, собственный скролл, фон затенён и недоступен клавиатуре. Закрытие по
Esc, фону или кнопке; фокус возвращается к инициатору, прокрутка страницы блокируется
на время открытия. На телефоне — полная ширина, отступ для safe-area снизу.

Черновик и выбранный ответ живут в родителе фильма, поэтому закрытие шторки не
стирает их. Переход на другой фильм/страницу сбрасывает черновик; offline-хранилища
нет. Повторная отправка отзыва блокируется до ответа. Для гостя перед открытием
авторизации шторка закрывается: модальное окно входа не остаётся за нативным dialog.

## Умная шапка

`MovieContextBar` наблюдает за постером через IntersectionObserver. Когда постер
уходит выше шапки, появляется компактная строка с названием, средней оценкой и
кнопкой «Буду смотреть». Поиск, аватар и навигация остаются доступны. ResizeObserver
учитывает изменение высоты шапки; нет постоянного React-обработчика scroll.
Кнопка использует общее оптимистичное состояние списка и те же проверки авторизации.
При возвращении к постеру или уходе с фильма строка исчезает, observers очищаются.

## Деликатное движение

- Tilt постера ограничен примерно 3,5° на ось; блик следует за мышью. Меняются CSS
  переменные DOM, не состояние React при каждом движении. Без постоянного will-change
  для сотен карточек. Сброс при уходе/отмене указателя.
- Магнит на кнопках любимого и желаемого смещает их максимум на 3 px внутри стабильной
  обёртки. Анимация иконки: двойное биение сердца, погружение закладки, исчезновение
  и возврат при удалении. Нет невидимой области, перекрывающей соседние кнопки.
- После успешного сохранения новой оценки 10/10 — короткая пульсация и 8 CSS-искр.
  При ошибке, повторе уже установленной десятки или простом наведении праздника нет.
- Иконки достижений слегка покачиваются при наведении; профильные значки открывают
  страницу с условиями. Нет звуков, вибрации и сторонней библиотеки анимаций.

Tilt и магнит работают только с мышью и fine/hover указателем. `prefers-reduced-motion`
отключает наклоны, смещения, искры, пульсацию, левитацию и анимированный переворот;
состояния и кнопки остаются работоспособными. Ответ на оценку и изменение списка
не ждут завершения анимаций.

## Тактильное представление достижений

Уже заслуженный тир обычной ачивки или раскрытый сервером скрытый трофей получает
кнопку переворота. Закрытые достижения не становятся доступными от клика.
Нераскрытые определения скрытых трофеев на клиент по-прежнему не отправляются.

Просмотр оформления запоминается локально ключом
`mg_achievement_reveal:<userId>:<achievementId>:<tier>`. Он отдельный для пользователя
и тира, поддерживает изменение в соседних вкладках. Это **не дата получения**, не
серверная активация и не синхронизация между устройствами. На первом посещении
предложено представить и старые заслуженные награды. При недоступном localStorage
взаимодействие не ломает страницу.

Переворот никогда не отправляет запрос награды, не начисляет XP/попкорн и не показывает
фиктивные «+50 XP». Подпись честная: «Награда уже засчитана». Это защищает существующую
экономику от повторных выдач и не скрывает условия/прогресс за обязательной мини-игрой.

## Проверки

- Unit: валидация настроений, приоритет редактора, жанровый fallback, старые значения.
- `tests/integration/responsive-ui.mjs`: настоящее React-дерево с фикстурами API,
  320–1920 px, настроения и сброс точных фильтров, сохранение оформления ачивки без
  POST, Esc/возврат фокуса и tab trap, спойлеры, реакции и ответ, черновик при повторном
  открытии, закрытие фоном, авторизация гостя, появление/удаление контекстной строки,
  отсутствие конфетти при ошибке, reduced-motion и очистка tilt. Команда запуска с
  необязательными браузерными зависимостями — в `docs/live-ui-storage.md`.
- Проверки браузерного fixture-runner не заменяют тест production-прокси/реальной БД.

Новых таблиц, миграций и зависимостей для этого слоя UI не требуется.
