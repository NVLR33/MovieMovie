# Город в верхней панели и отдельная афиша

## Интерфейс и память

`HeaderLocation` находится в компактной строке над существующей шапкой на всех страницах. Прежний раскрывающийся блок афиши убран с главной и из каталога. Ссылка «Афиша и сеансы» ведёт на `/showtimes`; страница также доступна в мобильном меню «Ещё».

Город выбирается вручную или через определение местоположения. Он запоминается **на этом устройстве** по умолчанию; галочка позволяет оставить его только на текущий визит. Формат прежний: `mg_city_v1 = {"city":"…"}`. Координаты, история перемещений и точный адрес в browser storage/БД не пишутся. Работа не требует аккаунта. При запрете storage выбор остаётся в памяти страницы и показывается предупреждение; при сбросе очищается и запомненный город. Вкладки синхронизируются событием storage.

## Реальная геолокация

- Никаких автоматических запросов разрешения при открытии сайта, IP-геолокации или watchPosition.
- Только кнопка «Определить местоположение» запускает браузерный getCurrentPosition.
- Перед нажатием объяснено, что округлённые координаты передаются через moviemovie в **OpenStreetMap / Nominatim**. В браузере они округляются до двух знаков до POST `/api/location`; сервер округляет повторно. Это ориентир для города, не точная позиция пользователя.
- Сервер делает fixed-origin reverse lookup с zoom=10, принимает city/town/village/municipality/hamlet, но не выдаёт область за город. Название проверяется прежним normalizeCity. Требуется подтверждение «Применить»; находка сама не сохраняется.
- Теперь определение не ограничено 24 городами локального справочника. При недоступности геокодера локальный nearbyCity остаётся **явно подписанной приблизительной подсказкой**, без автоматического выбора ближайшего далёкого города.
- Отказ, timeout, плохая точность, offline/ошибка источника, устаревший результат после редактирования/закрытия и ручной ввод обработаны. Запросы отменяются при закрытии/смене ввода.
- Сервер не логирует тело запроса/координаты/URL ошибок геокодера, отвечает no-store; cross-origin POST запрещён. Внешние запросы ограничены временем/размером ответа, redirect запрещён. В UI есть атрибуция OSM.

**Эксплуатация:** public Nominatim ограничен на уровне одного процесса минимумом 1100 мс между запросами; автодополнения к нему нет. Для высокой нагрузки или нескольких serverless-инстансов **до production-включения** нужен общий rate limiter/выделенный геокодер согласно [политике Nominatim](https://operations.osmfoundation.org/policies/nominatim/). Это не распределённая глобальная квота. `GEOLOCATION_ENABLED=false` выключает удалённое определение, не ломая ручной выбор. Переменные реального хостинга не менялись.

## Сеансы

`GET /api/showtimes?city=…&date=YYYY-MM-DD` получает данные открытого KudaGo API, а не парсит закрытые сайты и не придумывает расписание. Адаптер:

1. Загружает справочник locations (кэш процесса до суток) и ищет точное нормализованное имя города. Не подменяет Каменск-Уральский Екатеринбургом или Москвой. Неизвестные/невалидные timezone не используются для выдуманного местного времени.
2. Запрашивает movie-showings для указанного дня **в часовом поясе города**, связывает movie/place IDs отдельными пакетными запросами movies/places.
3. Отбрасывает прошлые, чужие даты, неполные записи и дубли. Цены/форматы показывает только если их прислал источник. Ссылки строятся на фиксированном домене KudaGo, не из произвольных provider URLs.
4. Ограничивает выдачу двумя страницами по 100 записей; частичный результат явно подписан. Присланные next URLs не запрашиваются. Кэш снимков — до пяти минут, максимум 96 записей процесса с объединением одинаковых in-flight запросов; сбой не кэшируется как пустой успех. Это небольшой локальный кэш, не распределённая система.

На странице: ближайшие семь дней, фильтр кинотеатра/фильма, группировка по фильму и площадке, местное время, адрес, известная цена и ссылка к источнику. «Обновлено» означает время загрузки снимка. Нет покупки внутри приложения, бронирования и гарантии мест/актуальности цен.

Отдельно показаны состояния **нет покрытия города**, **нет полученных сеансов**, **ошибка/повторить**, **нет результатов фильтра**. Внешний поиск находится в отдельном блоке и не называется загруженными сеансами.

**Ограничение:** KudaGo — источник с частичным покрытием городов/кинотеатров, не всеобщий билетный агрегатор. Для полного коммерческого покрытия нужна интеграция согласованного билетного провайдера с его условиями/ключами. Полнота для конкретного города не обещается.

Контракт сверялся с открытыми клиентами API: [Showings](https://github.com/larowka/kudago-api/blob/master/src/Methods/Showings.php), [Showing fields](https://github.com/larowka/kudago-api/blob/master/src/Resources/Showing.php), [пример пакетного получения movie/place](https://github.com/veraxxxo/cinemafinder/blob/main/scripts/sources/kudago.mjs). Эти ссылки объясняют контракт, но не гарантируют доступность сервиса сейчас.

## Проверка и ограничения песочницы

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- `test:location:browser`: настоящий production UI, контролируемые ответы `/api/location` и `/api/showtimes`; подтверждение GPS, округление/память/clear/cross-tab/отказ/timeout/ошибка/запрет storage, фильтры/дата/группы/timezone/empty/unsupported/retry, восемь ширин и фокус. Никакие личные GPS-данные не использовались.
- `location-showtimes.test.ts` проверяет server adapters/API validation, fixed-origin URLs, диапазоны дат/городской часовой пояс, неполные/неизвестные записи, ограничение страниц и запрет follow-next/redirect.
- `test:cine-day:browser`, `test:city-series:browser`, мобильный и actual-app smoke сохраняют связанные контракты.

Outbound доступ песочницы ограничен: **живые ответы Nominatim и KudaGo здесь не подтверждены**. Проверки используют подставленные provider responses. Перед публикацией нужны разрешённый smoke из среды хостинга, проверка политики геокодера и фактического покрытия нужного города. Ошибки реального источника остаются видимыми пользователю, не превращаются в демонстрационные сеансы.

Новых миграций, переноса БД, изменений production/хостинга/DNS или реальных env нет.
