# Аудит истории GitHub и полного CI MovieMovie

## Итог

В текущем коде воспроизведены и локально исправлены **две проблемы тестов**, мешавшие полному CI. После исправлений все команды проверок из workflow прошли локально на production-сборке и отдельной одноразовой БД.

**Это ещё не зелёный GitHub Actions:** исправления не закоммичены и не отправлены в рамках этого аудита. Состояние опубликованного сайта и его БД не менялось и этим прогоном не подтверждается.

## Что именно проверено

- Загружена полная доступная Git-история: 327 коммитов. Проверены граф, цепочка слияний и история относящихся к CI файлов; это не построчное ревью каждого из 327 коммитов.
- Получены все 16 PR, доступных через GitHub CLI: все объединены.
- Получены все 30 доступных запусков workflow `Code and route checks`, изучены статусы заданий и шагов.
- Сравнены деревья коммита `b860833` текущей ветки и `origin/main` (`0581781`, merge PR №16): **различий нет**. Предыдущие отправленные изменения присутствуют в main.
- Проверены установка из lockfile, аудит зависимостей, типизация, линтер, unit-тесты, пять интеграционных наборов, воспроизводимость SQL bundle, сборка и все 23 набора из HTTP/browser-этапа workflow.
- Все проверки БД выполнялись на локальной изолированной БД с защитным маркером. Реальные OAuth/Storage/внешние сервисы в соответствующих тестах подменяются контролируемыми фикстурами; реальная работоспособность внешних интеграций этим не доказывается.

## Найденные проблемы и исправления

### 1. Устаревшее количество миграций блокировало ранний этап

`tests/integration/popcorn-economy.mjs` ожидал 11 миграций, а текущий SQL bundle применяет 12. Воспроизведено `AssertionError: 12 !== 11`. Ещё два числовых ожидания в сценарии отката/повторного применения также устарели.

Исправление не подменяет 11 на 12 и не отключает проверку. Теперь тест читает текущий manifest файлов миграций и сравнивает **полный список имён и SHA-256** с журналом применения. После намеренно неуспешного upgrade проверяется точный список без pending-index migration, затем полный список после восстановления. Проверки схемы, drift detection, атомарного rollback и сохранения баланса оставлены включёнными.

SQL bundle и файлы миграций не изменились. `npm run db:bundle` даёт нулевой diff с закоммиченными SQL-файлами.

### 2. Селектор теста админки не учитывал реальный счётчик заявок

После `test:suggestions:browser` в изолированной БД остаются pending-заявки. Кнопка админки называется не только «Предложения», но содержит счётчик. `getByRole(..., {name: 'Предложения', exact: true})` не находил её и истекал по timeout.

Тест теперь ищет кнопку именно внутри навигации «Разделы управления» и допускает только точное название плюс необязательный числовой счётчик. Проверки всех шести разделов, ролей, блокировок, отзыва сессий и серверной приватности сохранены. Полный последовательный прогон на общей изолированной БД прошёл.

### 3. Диагностика и запас времени CI

- Пять интеграционных проверок теперь отдельные именованные шаги, а не одна длинная цепочка `&&`.
- Вывод каждого integration/browser-набора сохраняется в отдельный `audit-*.log`, файлы доступны как артефакты при сбое.
- Используется bash с `pipefail`: `tee` не превращает упавший тест в успешный.
- Общий лимит поднят с 25 до 45 минут: локальный browser/HTTP-прогон занял около 21 минуты, не считая установки, сборки и остальных этапов. Скорость GitHub runner может отличаться.
- Аннотация о Node 20 внутри actions v4 — отдельное предупреждение, не причина исследованного AssertionError. Крупные версии сторонних actions в этом исправлении не менялись.

## Что остаётся

1. Закоммитить и отправить исправления тестов/workflow в текущую ветку.
2. Получить новый запуск GitHub Actions и проверить его до конца. Локальный PASS не равен удалённому PASS.
3. Изменения отправлять отдельным PR: прежний №16 уже закрыт слиянием. В рамках этого аудита PR не создавался и ничего не сливалось.
4. Публикацию и состояние реальной БД проверять отдельно, по разрешению владельца. Этот аудит не является гарантией отсутствия любых ошибок или полным аудитом безопасности всего исторического кода.
